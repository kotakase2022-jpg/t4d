# 空のテナントの払い出し（手順書）

トライアル・本導入で、実データを扱う企業テナント（と、保証側を再現する場合の監査法人テナント）を作る手順。
運営だけが行う。アプリの画面からは払い出せない（顧客が自分で組織や有償オプションを作れないようにするため）。

> 実ユーザーの招待・実データの投入は、発注者の判断（解禁の指示）があるまで行わない（CLAUDE.md §0-6・§0-7）。
> 本番の公開 URL（Demo Mode 限定で公開している Vercel）には実データ・本番の Supabase を載せない。スクリプトもその環境では止まる。

## 1. 前提

- 対象の Supabase プロジェクトに、マイグレーション（`supabase/migrations`）と**マスターだけ**（役割・権限・基準と要求事項）が入っていること。
  架空のデモデータ（`supabase/seed.sql` の Fixture）は入れない。
- 実行する端末の環境変数に `NEXT_PUBLIC_SUPABASE_URL`・`SUPABASE_SERVICE_ROLE_KEY`・`NEXT_PUBLIC_APP_URL`（招待リンクの前に付く URL）。
  Service Role Key はこの端末の外へ出さない。
- 合意済みであること: 対象の組織名とコード、初期管理者のメールアドレス、報告年度、CDP オプションの契約の有無、保証側を再現するか。

## 2. 計画を確かめる（dry-run・既定）

```bash
pnpm exec tsx scripts/provision-tenant.ts \
  --org-name "<企業名>" --org-code <コード> --admin-email <初期管理者のメール> --fiscal-year 2026 \
  [--cdp --contract-ref "<契約の参照>"] \
  [--firm-name "<監査法人名>" --firm-code <コード> --firm-manager-email <メール> --engagement-code <案件コード>]
```

何も書かずに、作るもの（組織・本社・報告年度・開示優先モード ON・3 段階の既定の承認ルート・CDP オプション・
招待・監査法人・関係・最初の案件）と招待リンクを表示する。内容を発注者・顧客の担当と確かめる。

## 3. 実行する

```bash
pnpm exec tsx scripts/provision-tenant.ts <2 と同じ引数> --apply --confirm-project <プロジェクト ref>
```

- `--confirm-project` は Supabase の URL の先頭（`https://<ref>.supabase.co` の `<ref>`。ローカルは `local`）。
  書き込み先を人が確かめるための引数で、一致しないと止まる。
- マスター（役割・SSBJ の基準）が無い環境では止まる。
- 表示された招待リンクを**本人へ手渡す**（メールは送らない）。リンクは 14 日で失効する。失効したら管理者が設定の「招待」から発行し直す。

## 4. 監査法人のチーム（保証側を再現する場合）

監査法人のマネージャーが招待を受諾したら、最初の案件のチームに加える（案件の起票者でない人は案件を開けないため）。

```bash
pnpm exec tsx scripts/provision-tenant.ts --assign-members --firm-code <コード> --engagement-code <案件コード> \
  --member-email <受諾したメール> --apply --confirm-project <ref>
```

以降のメンバーの追加は、監査法人のマネージャーが案件の概要画面のチームから行う。

## 5. 払い出しの後

1. 初期管理者が受諾してログインし、設定の「メンバー」「招待」で担当者を招待する（担当拠点つき。受諾で担当範囲に写る）。
2. 設定の「承認ルート」で段階を確かめる（既定は 3 段階。過年度確定値の経路が要るならひな形から作る）。
3. 設定の「データの取扱い」で、合意したデータ取扱条件を版として記録する（未合意の項目は未合意のまま）。
4. 組織・拠点・指標・報告年度を整え、データの取込を始める。

## 6. 記録

- 払い出しの日時・実行者・プロジェクト ref・組織コードを運営の作業記録に残す（顧客のデータは書かない）。
- アプリの監査ログには、受諾・招待・設定の変更などアプリ内の操作が残る。
