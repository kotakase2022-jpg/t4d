## 0. 要約

1. 画面は 78 ルート（リダイレクト専用 3 を含む。`/enterprise/disclosures/[framework]` で MSCI・FTSE の 2 画面）。企業側 55・監査法人側 15・認証/共通 8。ページ＋同梱部品で 161 ファイル・約 4.5 万行あり、上位 3 画面だけで約 1 万行（原稿エディタ 4,072、開示プロジェクト詳細 3,844、財務影響分析 1,994）。

4. enum やコードがそのまま画面に出る箇所が 17 以上ある（例: 状態 `fieldwork`、ロール `assurance_manager`、指標カテゴリ `ghg` や集計方法 `sum`、権限キー `enterprise.data.read`）。英語のシステム用語も監査法人側を中心に残る（`Active Engagements`、`Procedure Checklist`、`Data Mapping`、`Reject`）。

### 1.2 頻度

日 = 毎日〜週に数回、週 = 週 1 回程度、月 = 月次や締めの時期、稀 = 年数回・初期設定、— = 開けない、または業務上使わない。

### 1.3 Primary の数え方

- `P a/b`: a はコード上に出てくる Primary の数（`Button`/`SubmitButton` で variant 指定なし、または `primary`。条件分岐の両方を含む）。b は 1 つの状態で同時に見える数の最大の見込み。「行×」は表の行ごと、「節×」は節ごとに繰り返すもの。
- 指示書の「One Screen One Primary Job」に照らし、**b ≥ 2 を違反**とする。

### 1.4 複雑度スコア（各 1〜3、合計 6〜18）

| 観点      | 1                                 | 2                                                      | 3                                                                                  |
| --------- | --------------------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| Nav       | メニュー 2 階層以内で現在地が明確 | 3 階層、メニューに無い（画面内リンクだけ）、名称不一致 | 片方のメニューから辿れない、同じ href が並ぶ、タブ＋戻るリンク＋次工程リンクが混在 |
| Action    | 見える操作 ≤3、Primary ≤1         | 4〜6、または Primary 2                                 | >6、Primary ≥3、または行・節ごとに Primary                                         |
| Info      | 区画 ≤3                           | 4〜6                                                   | ≥7、または同じ情報を重複表示                                                       |
| Form      | 入力なし、または ≤5 項目          | 6〜10、または複数フォーム                              | 1 フォーム >10 項目、行内フォームの反復、モーダル内の大きなフォーム                |
| Cognitive | 仕事が 1 つで業務用語だけ         | システム語や生コードが少し、または仕事が 2 つ          | 生 enum・英語のシステム語が多い、仕事が 3 つ以上、または状態で操作が食い違う       |
| Visual    | 平らで密度が高い                  | カード・バッジ・色付きの注記が多い                     | KPI カードを横 7〜9 枚並べる、カードの格子、色が主役                               |

### 1.5 フラグ

`P>1` = Primary の同時表示が 2 つ以上 ／ `A>6` = 最初の表示で見える操作が 7 つ以上 ／ `F>10` = 1 フォームで見える入力項目が 10 を超える ／ `RAW` = 生のコード・enum・英語のシステム語 ／ `EMPTY` = 次の操作を示さない空状態（「やることはない」という前向きな空状態は除く）／ `ERR` = 何を・なぜ・どう直すかが分からないエラー ／ `MODAL` = モーダルの使い方が不適切 ／ `LOAD` = 読み込み中の表示が無い（§2.1 のとおり全画面が該当） ／ `DNG` = 危険な操作の区別・確認・取り消し手段が無い ／ `ROLE` = 役割に合わない初期表示、または押すと失敗する操作

## 2. 横断所見（全画面に共通する事実）

### 2.1 Loading（全画面 `LOAD`）

- `loading.tsx` と `<Suspense>` は 0 件。理由は Next.js 15.5 の不具合を避けるためで（`app/assurance/layout.tsx:52-61`、`docs/known-limitations.md` S-11）、意図した設計。**このため画面単位のスケルトン表示を足すことはできない**。
- 共通部品の `LoadingState`（`cmp/shared/states.tsx:14`）は呼び出し 0 件。遷移中の表示は `LinkPending` の 3 か所だけ（ホームのタブ `app/enterprise/dashboard/page.tsx:95`、プロジェクトのタブ `app/enterprise/disclosure-projects/[projectId]/page.tsx:132`、原稿エディタ `block-editor.tsx:1163`）。サイドバーと表の行リンクには遷移中の表示が無い。
- 送信中の表示は `SubmitButton`（`cmp/ui/submit-button.tsx:24-33`）が担っているが、`Button type="submit"` をそのまま使う箇所が多く、そこでは押した後の反応が出ない（例: `app/enterprise/data/[dataPointId]/page.tsx:267,277,294,317`、`app/enterprise/settings/page.tsx:176,261,462`、`app/assurance/engagements/[engagementId]/requests/page.tsx:128,207`）。

### 2.3 エラー表示（`ERR`）

- 本番では `error.tsx` に `digest` しか届かず、表示されるのは「識別子: …」と再試行ボタンだけ（`app/enterprise/error.tsx:12-20`）。`error.message.includes('権限')` による権限エラーの判定も、本番ではメッセージが伏せられるため常に偽になる。
- 権限エラーの文言にシステムの権限キーがそのまま入る。例: 「権限 enterprise.disclosure.write が必要です。」（`src/lib/authorization/can.ts:47`）、「出力には出力の権限（enterprise.export.run）が必要です。」（`svc/disclosure-export.ts:92`）。状態遷移のエラーも「draft から approved への遷移は許可されていません」のように enum のまま出る（`svc/data-point-workflow.ts:115`）。どれも「誰に頼めばよいか」を書いていない。
- 出力 API は権限が無いと `NextResponse.json({ error: 'forbidden' }, 403)` を返す（`app/api/exports/data-points/route.ts:25-27`、cdp も同じ）。一方で、出力ボタンは権限が無くても表示されている（`app/enterprise/reports/page.tsx:38`、`app/enterprise/data/page.tsx:181,190`、`app/enterprise/disclosures/cdp/page.tsx:244`）。

### 5.6 モーダルの使い方（MODAL）

Dialog を使っている画面は組織・拠点だけ（`organizations/master-forms.tsx`）。指標マスターの 19 項目のフォームをモーダルに入れているのは、指示書の「モーダルは確認・小さな編集・危険操作・その場での選択だけ」に反する。逆に、確認が必要な破壊的操作（§2.4）にはモーダルもインラインの確認も無い。`window.confirm` は原稿エディタで未保存のまま離れるときの 1 か所だけ（`block-editor.tsx:401`）。

### 5.7 役割に合わない初期表示・失敗する操作（ROLE）

- ホームは全役割で同じ構成（`dashboard/page.tsx:35-50`）。拠点担当・サプライヤー担当は、開示優先モードだと最初の表示が「権限がありません」（`disclosure-home-view.tsx:130-137`）。
