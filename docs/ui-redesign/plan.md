## 0. 要約

### 0.1 決定事項（16 項目）

1. **機能・業務ロジック・権限検査・API・データ項目は 1 つも消さない**。単純化は「置き場所（L1/L2/L3）」「役割で変わる初期表示」「状態で変わる操作」「既定値」で行う。権限の 2 層（`roles.ts`・`0002_identity.sql`）、DB スキーマ、RLS、API ルートは変えない。
2. **メニュー木の形は変えない**（従来・開示優先とも。ラベル・href・入れ子・permission・並び・現在地の規則は unit と E2E で固定済み）。変えるのは①グループの開閉（既定は開。利用者ごとに記憶）、②開示の閲覧権限が無い役割では「開示対応」「開示プロジェクト」を既定で閉じる、③監査法人ツリーの再編（固定テストなし）の 3 点だけ。
3. 役割の違いは**ホーム**（`/enterprise/dashboard` の先頭に「自分の作業」＝ Attention → Action を追加）、**Command Palette のおすすめ**、**画面の主操作（状態 × 権限）**で出す。従来ホームの KPI 9 枚とリンク（A39）は Status 段として残す。
4. タスク動詞（入力する・直す・確認する・承認する・回答する・取込を確認する・原稿を書く・レビューする）の入口は、**新しい画面を作らず**既存 URL＋絞り込みに名前を付けて、ホームとパレットに置く。
5. 画面の主操作は **1 つ**。`Button` の既定 variant を `secondary` にし、全 variant が `data-variant` を DOM に出す。E2E で「main 内・ダイアログ外で見えている `[data-variant="primary"]` は 1 個以下」を全ルート × 役割で検査する（Stage A は現状をスライス別の許容リストに固定し、B で空にし、C で厳格化）。
6. 副操作は見出しに最大 2 つ、それ以外は文字付きの「その他 ▾」。行の操作は「主な 1 操作（文字）＋操作 ▾」。一括操作は**行を選んだときだけ**下端に出る。
7. 危険な操作は 3 区分で 1 つの部品（`ConfirmDialog`）に揃える。不可逆＝確認＋範囲 1 行（リセットは必須チェックを維持）、一括・上書き＝件数と内訳のプレビュー＋確認、可逆＝実行後に「元に戻す」付きの通知。差戻しは全画面で理由を必須（UI 層。サービスは変えない）。
8. 一覧は共通の `DataTable`（見出し固定・検索・絞り込み・並べ替え・ページ送り・列の表示切替・保存ビュー・一括選択・行操作・展開行・先頭列固定）へ寄せる。**列の表示状態は URL の `cols` を正**とし（サーバー描画で DOM から外す。既存 E2E と整合）、利用者ごとの既定ビューと名前付き保存ビューは localStorage に持ち、**アプリ内リンク（サイドバー・パレット・ホーム）に既定ビューのクエリを付けて遷移する**ことでレイアウトのずれを出さない。
9. 作成フォームは一覧の上に常設しない。`?new=1` で開く `CreatePanel`（JS 不要・既定で閉じる）にする。19 項目の指標マスターと 115 チェックのキャンペーン作成は**専用ページ**へ移す（新ルート 3 本。モーダルの誤用 MODAL を解消）。
10. Command Palette は「最近使った画面（localStorage）→ 役割のおすすめ → 操作 → 画面（メニュー外の 11 画面を含め重複除去）→ 設定の項目 → データ（指標・拠点・要求事項コード・プロジェクト・原稿・定性情報・資料・案件・メンバー）」を引く。データ検索は**読み取り専用の Server Action を 1 本追加**（既存サービスの読み取りだけを呼び、`can`＋RLS を通す。DB・権限は変えない）。
11. 文言は業務の言葉へ。生の enum・ロールキー・権限キー・内部 ID・英語のシステム語は、ドメイン別の**状態登録簿**とラベル辞書から出す。CLAUDE.md §8 の用語（Data Room・Snapshot・PBC・Sign-off など）は残す。
12. エラーは「何が・なぜ・どうする」。業務エラー（`AuthorizationError`・`ValidationError`・`NotFoundError`）を投げる Server Action は**すべて既存の `withUserFacingError` で `?error=` に載せ替える**（`enterprise/actions.ts` 58＋`assurance/actions.ts` 16 の計 74 のうち包まれているのは 24、監査法人は 0。`'use server'` 全 145 では 53。`useActionState` で結果を返すものは対象外）。権限エラーの文言から権限キーを外し、権限名と頼む相手を書く（「権限」の語は残す。既存の `toThrow(/権限/)` は通る）。
13. Loading 境界（`loading.tsx`・Layout の `<Suspense>`）は**置かない**（S-11。Next.js 15.5 の不具合で Client 遷移が固まる）。代わりに AppShell の上端プログレス、送信中の `SubmitButton`、クライアント部品内の固定高スケルトンでレイアウトのずれを防ぐ。
14. デザイントークン（文字サイズ 9 段・warning-ink・overlay・z-index・影・角丸・段組・欄幅）を `globals.css` に足し、**計算後の CSS が変わらない置き換えだけ**を Stage A の codemod で行う（文字サイズのトークンは line-height を持たせない＝`text-[12px]` と同じ宣言になる）。残りは C で仕上げ、ESLint で再発を禁じる。
15. 誠実さの注記（デモ・架空・Mock・AI は候補・未発効・試算・提出ではない・転載許可）は**常に見える場所に残す**。`HonestyBadge` に集約し、`Collapsible` の中へ入れない。AI が承認・確定する経路は作らない（パレットの「承認する」は一覧へ移動するだけ）。
16. 実装は 3 段: **Stage A（1 エージェント）**＝土台（トークン・部品・ナビ・役割ホーム・パレット・自動検査・ベースライン）→ **Stage B（6 スライス並行）**＝画面（78 ルートを 1 ルート 1 スライスで所有）→ **Stage C（1 エージェント）**＝統合（codemod 仕上げ・横断 spec・全ゲート・E2E 通常＋stateless・回帰報告）。デプロイと push はしない。

### 0.3 指示書全文で補ったもの（棚卸しは要約を基に書かれていた）

- §11 Column Resize・Column Pinning: 先頭列の固定は `DataTable.columns[].pinned` で扱う。**列幅の手動変更（Resize）は扱わない**（PC 1280px 以上・列の既定幅トークンで足りる。§7 に記す）。
- §22 Optimistic UI: 通知の既読・コメント投稿・ナビの開閉・保存ビューに限って `useOptimistic`／即時反映を使う。業務データの状態遷移には使わない（失敗時に誤った確定表示を出さないため）。
- §10 Wizard: 段階 UI は `StepNav` に揃える（標準 CSV・プロジェクト作成・CSRD 設定・サプライヤー取込・キャンペーン作成）。
- §37 Phase 3 の Toast・Tooltip・Header・Sidebar: Toast は消えない通知（`Notice`）で代替（消えるトーストは必要な情報を隠すため）。Tooltip は `Hint`（キーボード・タッチで読める）。Header にパレットの起動ボタン（文字「検索」＋`Ctrl K`）を足す。
- §33 判断基準の順（業務目的 → 頻度 → 認知負荷 → 操作回数 → 情報密度 → 見た目）: 本書の個別判断はこの順で決めた（例: ESG データの「Evidence」ラベルは業務用語ではないが、明示要望で固定されたメニューのため変えない）。

### 1.6 One Screen, One Primary

- 1 画面（タブがあればタブごと、状態で変わるならその状態ごと）に `variant="primary"` は 1 つ。ダイアログの中も 1 つ（確定ボタン）。
- primary は「その画面の仕事」に付ける。**次工程へのリンクを primary にしない**（E21 `ssbj/collection:64`・E28 `csrd/plans:123`・E29 `csrd/collection:272` は secondary へ）。
- 行ごと・節ごとに primary を繰り返さない（E01・E02・E22・E30・A10・A11）。行の主操作は文字リンクか xs の secondary。
- 状態で primary が変わる画面は §1.15 の表に従う。
- primary を付ける操作が無い画面（閲覧専用の分析など）は 0 でよい。

### 1.9 Recognition over Recall

- **最近使った画面**: `RecentTracker`（AppShell のクライアント部品）が遷移ごとに `{ href（flash・error を除く）, label（main の h1）, at }` を localStorage `t4d.recent.v1.<viewerKey>` に最大 20 件保存。読めない環境（プライベート・拒否）では何もしない（try/catch。描画は保存の有無に依存しない）。
- **保存ビュー**: 既存の固定プリセット（data・cdp・ssbj/csrd 要求事項）＋利用者が名前を付けて保存したもの（localStorage `t4d.table.v1.<viewerKey>.<tableId>`）。共有は URL のコピー。
- **候補選択**: 指標・拠点・部署は `<datalist>`／`NativeSelect` の候補から選ぶ（コードを覚えさせない）。
- **名称の統一**: 同じ画面はメニュー・h1・タブ名（metadata）・パンくずで同じ名前（IS §2.6 の不一致を解消。メニューの固定ラベルに h1 とタブ名を合わせる）。
- **前回値・前年値**: D7。

`viewerKey` は `${userId}:${workspaceId}`（デモの役割切替で利用者が替わっても混ざらない）。AppShell が `ViewerContext` で配る。

### 1.12 Table の規則

1. 一覧は `DataTable` を使う（§3.2）。埋め込みの小さな表（≤15 行・操作なし）は `Table` のままでよいが、見出し固定は `Table` の既定にする（2 方式を 1 つに）。
2. 初期表示の列は `importance: 'primary' | 'secondary'` だけ（目安 7 列以下）。`detail` 列は「列 ▾」で出せる。**CSV・XLSX の列は変えない**。
3. 並べ替えはサーバー側（URL `sort`・`dir`）。インメモリの一覧もページで並べてから切る。
4. 検索・絞り込みは `FilterBar`。チップは 2 群まで、残りは「絞り込み ▾」。絞り込み結果 0 件の空状態は「絞り込みを解除」を自動で付ける。

### 1.13 Form の規則

リスクと対策:

- **E2E の大量の手直し**: 操作を L2 へ移すと多くの spec が「開いてから」に変わる。§5.3 の 3 種類に限り、skip ガードで黙った skip を防ぐ。B はファイル所有で衝突を避け、横断 spec は C がまとめて直す。
- **localStorage の既定ビュー**: 直接 URL を開いたときは既定の列になる（意図どおり）。描画後に書き換えないため、ずれは出ない。利用者が「既定にしたのに違う」と感じうる点は、一覧の上の「既定のビュー: {名前}（適用）」リンクで補う。
- **codemod**: 計算後の CSS が同一のものだけを A で置換し、画素差 0 で確認する。行の高さの統一は扱わない。
- **Stage A の規模**: 部品が多い。A の内部の順（A0〜A9）を守り、各段の unit を先に書く（CLAUDE.md §3）。
- **パレットのデータ検索**: 既存の list 関数を呼ぶため、件数が多い組織では遅くなりうる。各グループ 8 件・2 文字以上・待ち時間で抑え、遅い場合は known-limitations に記す。

今後（本計画の対象外）: 列幅の手動変更（Column Resize）、行の高さ・文字の line-height の統一、SsbjFlow・DisclosureSteps の `StepNav` への統合、IF §7.3 の権限ゲートの一般化した静的解析、保存ビューの組織での共有（DB が要る）、Next.js 16 での Loading 境界の復活（S-11）。
