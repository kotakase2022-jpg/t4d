## 2. plan からずらしたこと（理由）

1. **SSBJ 要求事項の詳細で `CandidateDecision` を使っていない**。部品の「候補を採用」フォームは隠し項目だけで、既存の「確認コメント（履歴に残ります）」を送れない（採用時の根拠が消える）。確定後の再判定（判定の付け直し）も部品に入口が無い。代わりに同じ規則（候補なら確定が primary、確定後は次の操作が primary、AI 分析は secondary、候補の表示は外）を画面で実装した。C で部品に `fields` 付きの採用（入力欄を含められる）を足すなら寄せられる
2. **マテリアリティの行操作は `RowActions` でなく、行のボタン 2 つ（編集・削除…）**。編集は行内の開閉（クライアントの状態）で、`RowActions` は Server Action・リンクの `ActionSpec` しか受けないため。削除は `ConfirmDialog` を通す
3. **回答画面のコメント欄は閉じない**（plan S6 は「1 件以上で開く」）。ショートカット「c」（コメント入力へ移る）が閉じた節の中では効かないため（指示書 §10 Expert）。件数は見出しに出す
4. **回答の差戻し理由はコメントとして残す**。`transitionDisclosureResponse` は理由を受け取らない（サービスは変えない）。理由欄を必須にしたまま捨てないよう、状態を戻せたら既存の `addCommentAction` で「差戻し理由: …」を残す（`_components/return-response-dialog.tsx`。Server Action は増やしていない）
5. **F048 の引継ぎは成功しても通知が出ない**（`carryOverSsbjAction` が flash を付けないため。凍結の `enterprise/actions.ts`）。C で `?flash=` を付けるなら `flash-messages/ssbj-cdp.ts` に文言を足す
