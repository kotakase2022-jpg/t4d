# 村田製作所向けデモ: Scope3 Cat.1 サプライヤーデータ取込（20 ファイル・240 明細）

すべて**架空のデモデータ**です。実在のサプライヤー・実測データ・第三者検証済みデータではなく、
係数（DEMO-EF-\*）は架空の説明用係数で実算定には使用できません。

## 1. 起動とデモモード

- 本番デモ環境: https://terrast-t4d.vercel.app （Demo Mode 固定・環境変数なし）
- ローカル: `pnpm dev` → http://localhost:3000
- デモログイン画面から `sustainability@demo.local`（サステナビリティ推進部長）を選ぶ。
  取込には「取込の実行」権限が必要（site-user 等では投入フォームが出ない）。
- デモモードの判定はアプリモード（環境変数が無い＝Demo Mode）で行われ、
  **ファイル名によるデモ判定はしていない**。デモモードの画面には
  「デモ環境｜サンプルデータ・表示スコアはシミュレーションです」の注意書きが常時出る。

## 2. データの取得

- 画面内: 「GHG → Scope3データ取込 → Cat.1」の
  「Scope3 Cat.1 デモデータセット」カードからダウンロード
  - **投入用 ZIP**（`/demo/murata-scope3-cat1-upload.zip`）… 20 ファイルのみ
  - **一式 ZIP**（`/demo/murata-scope3-cat1-full.zip`）… upload + reference（正解データ等）+ 本書
- リポジトリ: `demo-data/murata-scope3-category1/`（`upload/` は 20 ファイルのみ。README や JSON は置かない）
- 再生成: `pnpm exec tsx scripts/generate-murata-dataset.ts`（決定論・何度実行しても同一内容）

## 3. デモ操作台本（3〜5 分）

1. **リセット（30 秒）** — 「GHG → Scope3データ取込 → Cat.1」最下部の「デモのリセット」カード。
   削除範囲の説明を読み、確認チェック → 「取込済みの算定版をリセットする」。
   一次データ合計が初期値 **143.1 t-CO2e** に戻る。
2. **一括投入（1 分）** — 投入用 ZIP を展開し、20 ファイルを**全選択して**取込フォームへドロップ。
   自動で解析が始まり、ファイル別の解析結果と全体サマリー
   （20 ファイル・明細 240 行・信頼度 最小/平均/最大・80〜97% 内の割合）が出る。
3. **解析結果の説明（1 分）** — 見どころ:
   - 信頼度は 80〜97% に分布（90〜96% 中心）。セルにマウスを載せると実測スコアが出る
     （表示はデモ用シミュレーションで、実測値は書き換えずに保持）
   - `02_燕青チタン` の合計行、`05_琥山電子材料` の注記行は「取込対象外」として除外
     （明細と二重計上しない）
   - `05` は g → kg、`20_播磨精密加工` は 円 → 千円 へ自動換算
4. **係数候補の選択（1 分）** — 候補行はセレクトに★推薦が初期選択済み:
   - `03_深山金属粉体`: ニッケル 2 行（生産国一致 → NI-JP ／ 海外調達 → 世界平均 NI-GLB）
   - `09_Penang`: アルミナ 2 行（Malaysia → MY 係数 ／ Japan → 世界平均）
   - `15_深圳華聯電路板`: セラミック基板は **3 候補**（地域・年・境界・理由を比較して選ぶ）
   - `19_みずほ紙器`: 副資材（金額）2 行は推薦なし → 人が汎用係数（例: EF-PUR-PACK 包装資材）を選ぶ
   - 係数を変更するとその場で排出量が再計算される
5. **確定（30 秒）** — 「チェックした行を確定する」。
   Scope3 Cat.1 の算定根拠へ新しい版が追記され、一次データ合計が
   **6,760.3 t-CO2e**（既存 13 社 143.1 + 新規 20 社 6,617.2）になる。
   GHG 画面の内訳可視化・原単位の紐づけ状況（再紐づけ）へ遷移して締める。

## 4. リセットと再現性

- リセットの削除範囲は「この組織 × 当期の Scope3 Cat.1 に取込・再紐づけで積まれた算定版」のみ。
  初期の算定内訳（版 1）・Data Point・承認履歴・他指標・ログイン情報・ブラウザの他の
  保存領域（localStorage 等）には触れない。`localStorage.clear()` のような全消しはしない。
- リセット → 同じ 20 ファイルを再投入 → 同じ結果（integration テストで検証済み）。
- 同じファイルの**二重投入**は「既存の内訳を置き換え」と明示され、合計は変わらない
  （黙って二重計上しない）。

## 5. 既知の制約

- **保存はブラウザ（インスタンス）単位**: Demo Mode の状態はサーバープロセスのメモリ＋
  Cookie 持ち回り（約 7.6KB）で保持される。240 明細の算定版は Cookie 上限を超えるため
  **Cookie では持ち回れない**（docs/known-limitations.md D-3）。同一インスタンスに
  当たっている間は表示されるが、Vercel が別インスタンスへ振ると確定結果が見えないことがある。
  デモ本番では「投入 → 確定 → そのまま同じタブで内訳を見せる」流れを推奨。
- **別ブラウザでのデモ準備**: 状態はブラウザ間で共有されない。別ブラウザ・別端末で
  やり直す場合は、その場で ZIP をダウンロード → リセット（不要なら省略）→ 20 ファイル投入、
  の順にそのまま実施すればよい（投入 1 分で同じ結果が再現される）。
- **期間の扱い**: ファイルの購入月は 2025-04〜2026-03（アプリの FY2025 に相当）だが、
  サプライヤー取込は購買日で期間検証をしないため、現行の収集期間（FY2026）の
  算定根拠として取り込まれる。デモでは「前年度実績の一括取込」という説明で扱う。
- **PDF は対象外**: サプライヤー取込は規則ベースの表解析（CSV/Excel）。PDF の表再構成は
  OCR/AI 解析基盤の新設に当たるため対象外とし、指示書の標準構成の PDF 4 件は
  XLSX に置き換えた（総数 20・内容は維持）。
- **リセットはインスタンス内の共有状態に効く**: Demo Mode の状態はサーバープロセスで
  共有されるため、同じインスタンスに当たっている別の閲覧者が積んだ算定版も
  リセットで消える（対象は架空データの算定版のみ。デモ用途として許容し、
  複数人で同時にデモする場合はリセット操作を 1 人に限定する）。逆に、別インスタンスで
  確定された版はリセットが届かないことがある（上記 D-3 と同じ制約）。
- 信頼度のデモ表示（80〜97%）は**表示のみ**。承認・自動確定・行の取込可否の判断には
  使われず、どこにも保存されない（デモ解除後に実測値として復活しない）。

## 6. 検証コマンド

```bash
pnpm vitest run tests/integration/murata-scope3-demo.test.ts
```

実パーサー・実保存処理を通した検証（20 ファイル解析・240 明細・信頼度分布・
独立計算の正解データとの照合・候補変更の再計算・二重投入・リセット再現）。
