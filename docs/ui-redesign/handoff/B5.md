## 2. plan からずらしたこと・決めたこと（理由）

1. **既存の Server Action（F107〜F112）はそのまま呼び、ページ側に薄いアダプタを置いた**。`createMetricAction` などは業務エラーを `/enterprise/organizations?error=` へのリダイレクトで返す（凍結の `enterprise/actions.ts`）。そのまま専用ページ・作成パネル・ダイアログから送ると、入力が消えて別のタブに飛ぶ（plan §1.13-5 に反する）。各ページの `'use server'` の関数（エクスポートしない）が既存の Action を呼び、`?error=` のリダイレクトを受け止めて理由を取り出し（`organizations/_lib/form-adapter.ts` の `runKeepingInput`。Next の redirect の digest から `error` を読む）、`PreservingForm` の失敗の状態として返す。成功したら同じタブへ `?flash=` 付きで戻す。新しい Server Action の export は増やしていない（到達性・業務エラーの検査は既存の Action のまま通る）。C が `enterprise/actions.ts` の 6 つに「戻り先（backTo・成功時の行き先）」を受ける形を足せば、アダプタは消せる
2. **指標マスターの「求めている基準」の列は既定で見せる**（plan は detail）。「指標マスターにどの開示基準が求める指標かを出す」は発注者の明示要望（`ssbj-settings-approval-draft.spec.ts` ①・`new-features-audit.spec.ts` ①）で、既定で隠すと「必要な情報を非表示にする」（指示書 §34）になるため。既定の列は 6（≤7）
3. **組織の編集は展開行ではなく、行の「編集」→ 一覧の上の編集パネル（`?edit=`）**。55 行それぞれの展開行に親組織の選択（55 件）を持つフォームを埋め込むと DOM が肥大化する（旧実装がダイアログ 1 つにしていた理由と同じ）。JS なしで開き、パンくず・戻るで閉じられる
4. **報告年度の追加はダイアログのまま（plan どおり）だが、送信は `PreservingForm`**。理由が出たらダイアログを開いたまま示し、入力を残す（旧実装は送信と同時に閉じて入力が消えた）
5. **規制対応度の行の並び（基準の順）は変えていない**。並びは `analysis.spec.ts` が固定しているため。「未判定の基準を先頭」は先頭の注意の帯（基準ごとの人が未判定の件数）で満たした
6. **GHG の推移（直近 3 年）は連結集計の節の中のまま**（plan の並びは「連結・Scope 別 → 推移」）。推移は連結値の推移で、連結集計と同じ数値の読み方の注記（内部取引控除の適用年）を共有するため
7. **サプライヤーの提出状況の表は既定で「未提出」**（plan どおり）。取込の確定後に提出済みを確かめる E2E は絞り込みを「提出済み」に切り替えてから確かめる（下の §4）
8. 列の表示（`cols`）を切り替えた AI の実行記録は、URL が表を指すので開いて描く（§1.5 の規則）
